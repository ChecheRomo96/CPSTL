Automated physical tests: ATmega2560

This Windows PowerShell 7 runner builds a dedicated CPSTL contract suite with Arduino CLI, flashes an Arduino Mega 2560 through its serial bootloader using avrdude, and checks the actual board's serial test results. It does not burn a bootloader, change fuses or use a simulator.

The runner described here targets the Mega. A separate STM32 Arduino candidate uses the same cases and a report in RAM for ST-LINK-only connections; its execution status is recorded separately and must not be inferred from the successful AVR runs below.

Requirements

  • Arduino Mega 2560 connected over USB, identified by Arduino CLI.
  • PowerShell 7 or newer.
  • Arduino CLI on PATH or supplied using -ArduinoCli. The script also locates the CLI bundled with a WinGet-installed Arduino IDE.
  • The arduino:avr platform installed in Arduino CLI's default data directory.
  • The serial monitor closed so the test command can use the port.

Run

From the CPSTL repository root:

./scripts/test-hardware.ps1 -Port COM3
./scripts/test-hardware.ps1 -Port COM3 -Allocation CPP

Select the board's actual COM port. The target is explicitly arduino:avr:mega:cpu=atmega2560; this first version does not support other boards. The test replaces the application firmware currently on the board.

To use a CLI outside PATH:

./scripts/test-hardware.ps1 -Port COM3 -ArduinoCli C:/tools/arduino-cli.exe

-TimeoutSeconds 30 controls the serial test deadline. Compilation and upload also have bounded deadlines (120 and 45 seconds respectively). Failure to compile, upload, verify or receive a complete test run causes a nonzero script exit. The script terminates its own subprocess tree if its deadline expires.

What runs on the board

tests/Arduino/CPSTLHardware/Cases.h is the expected case manifest. The firmware runs 23 cases covering:

  • type traits and numeric limits against the AVR C headers, including 16-bit int;
  • copy, fill, find, sort, iterator helpers, reverse iteration and back insertion;
  • vector growth, insertion, erasure, copy/move and element lifetimes;
  • strings, conversions, termination and mutation;
  • stack and queue order;
  • unique ownership, construction in raw memory, callable copy/move and utilities;
  • controlled allocator failure and allocation size boundaries.

The firmware uses C++11 and the CPSTL implementation, with C allocation by default. CPP selects the Arduino core's nothrow new/delete support. STD allocation and STL mode cannot be tested on this AVR toolchain, which has no C++ standard library.

This is a dedicated embedded contract suite, not the complete desktop GoogleTest suite. It does not establish every desktop case, real system-wide out-of-memory behavior, heap fragmentation endurance, stack high-water marks, interrupt safety or timing guarantees. Simulated allocation failures use a test allocator and check unchanged contents and outstanding allocation counts.

Evidence and failure detection

Every invocation creates build/hardware/atmega2560/<allocation>-<build-id>/. It records board identity/core/tool versions, source revision and dirty state, the RoModularBuild revision, exact CLI argument arrays, compilation log, firmware and SHA256, and the verbose avrdude command and verification log.

After upload, the host requests the freshly compiled build ID over serial at 115200 baud. It requires a matching BEGIN, one PASS/FAIL for every manifest case, and a matching END with consistent counts and positive assertions. Duplicate cases, unknown cases, missing results and timeouts cannot pass.

Complete runs produce serial.log, junit.xml and result.json. Runs that fail earlier still produce result.json with the error; a missing JUnit report is not a successful run.

To check that board-reported failures propagate to the host:

pwsh -NoProfile -File scripts/test-hardware.ps1 -Port COM3 -InjectFailure
# Expected: first case FAIL, a complete summary with one failure, exit code 1.
# Afterwards restore and test the normal firmware:
./scripts/test-hardware.ps1 -Port COM3

The failure injection only changes the first case's reported verdict. It does not intentionally damage memory or induce unsafe behavior.
